# 项目、数据与贡献边界

最后更新：2026-08-14

## 1. 项目目标

项目实现一个可因果流式运行的单通道语音增强前端，并用严格的 paired protocol 回答：

1. 经典统计增强和预训练 RNNoise 在什么条件下有效或失败；
2. 离线算法如何变成 persistent-state、任意 chunk、延迟可追踪的实时模块；
3. 感知增强是否改善固定 Whisper 后端的 WER。

系统边界为：

```text
microphone/WAV
→ 输入契约、重采样、VAD
→ MCRA + DD-Wiener 或 RNNoise
→ enhanced audio、VAD、延迟和 RTF
→ 人工监听、通话链路或固定 ASR 评测
```

项目不包含完整的 AEC、beamforming、dereverberation、AGC、目标说话人分离或 Whisper
微调。它们是工业音频系统的相邻模块，不能作为本项目已实现贡献。

## 2. 数据与 partition

音频来自 [VoiceBank + DEMAND 官方数据](https://datashare.ed.ac.uk/handle/10283/2791)。
所有 clean/noisy pair 使用相同 polyphase 参数从 48 kHz 降到 16 kHz，不分别做 peak
normalization，并把官方 `noise/snr_db` 日志写入 manifest。

| Partition | Pairs | Speakers | 时长 | 当前用途 |
|---|---:|---:|---:|---|
| development | 8,348 | 20 | 6.688 h | 选参、诊断、ASR full 待运行 |
| validation | 3,224 | 8 | 2.703 h | 未见 speaker 冻结验证 |
| official test | 824 | 2 | 0.576 h | 补充结果，非完全盲测 |
| 合计 | 12,396 | 30 | 9.967 h | speaker/utterance 全隔离 |

固定 seed `20260724` 将官方 28-speaker train 分为 20-speaker development 和
8-speaker validation。`development_balanced_5` 为 `20×5=100` 条快速子集；冻结后的
`validation_stratified_320` 从每个 `speaker×noise×SNR` stratum 确定性抽 1 条，共 320 条。
它用于以较低计算量检查跨 speaker/条件方向稳定性，不等同于 full corpus 的自然分布估计。

Development noise 为 `babble/cafeteria/car/kitchen/meeting/metro/restaurant/ssn/station/traffic`，
SNR 为 `0/5/10/15 dB`；official test 的 SNR 为 `2.5/7.5/12.5/17.5 dB`。

项目早期使用过 official test 中的 `p232_005` 做路线选择，因此当前核心泛化证据来自
8-speaker validation，official test 只作补充。

## 3. ASR reference

VoiceBank 音频包没有 transcript，不能把 clean 音频的 ASR 输出当作 reference。项目使用
[VCTK 0.92 官方包](https://datashare.ed.ac.uk/handle/10283/3443)中的人工文本：

- 12,396 个目标 utterance 的结构映射已完成；
- 缺失、重复、空文本和 speaker mismatch 均为零；
- reference 与 hypothesis 在同一个冻结 Whisper 环境中调用同一个 English normalizer；
- 每个 partition 仍有 3 条人工听辨核对待完成；
- 原始 transcript 和大包保留在 T7，许可核对前不提交正文。

## 4. 数据完整性

下载来源、精确字节数和 checksum 固定在
[`configs/data_sources.json`](../../configs/data_sources.json)。预处理和审计入口为：

```text
scripts/download_voicebank.py
scripts/prepare_voicebank.py
scripts/audit_full_protocol.py
scripts/prepare_asr_references.py
```

审计硬约束包括：安全解压、ZIP CRC/SHA、单声道有限值、clean/noisy stem 和长度一致、
16 kHz 输出、speaker/utterance 无泄漏以及 manifest 原子写入。

## 5. 贡献归属

| 模块 | 来源 | 本项目贡献 |
|---|---|---|
| VoiceBank/VCTK 数据 | 官方数据集 | 下载校验、配对、重采样、manifest、split 和审计 |
| STFT/WOLA、VAD、MCRA、Wiener | 经典文献算法 | 独立实现、流式状态、参数协议、实验与失败定位 |
| RNNoise 网络、特征和权重 | Xiph official RNNoise | 不训练、不宣称模型创新 |
| RNNoise C wrapper | 本项目 | C 签名、PCM 幅值契约、生命周期和错误检查 |
| 16/48 kHz streaming | 本项目 | 状态化 FIR、任意 chunk、flush/reset、固定延迟 |
| R4/C1 | 本项目实验 | 可复现负消融，不作为默认方案 |
| Whisper `small.en` | OpenAI official implementation | 固定后端接入、reference、缓存、评分、v2 路由 |

准确表述是：

> 我没有训练 RNNoise 或提出 MCRA/Wiener；我实现了经典基线、预训练 RNNoise 的实时工程
> 适配、严格数据和延迟协议、完整条件评测，以及固定 Whisper 下的增强影响分析。

## 6. 当前完成度

已完成：

- 12,396 对数据和 transcript 结构审计；
- validation 3,224 与 official test 824 的增强全量结果；
- RNNoise persistent state、48/16 kHz 和任意 chunk；
- 固定 ASR v1、稳健 v2、评分和中断续跑；
- ASR development balanced 100 条四路诊断；
- ASR validation 分层 320 条四路 v1/v2、稳定性分析和缓存复跑。

尚未完成：

- VCTK reference 的 9 条人工听辨抽查；
- ASR development full、validation full 和 official test（当前满足停止条件，按需再扩）；
- DNSMOS P.835；
- 真实麦克风多场景盲听和长期流式压力测试。

暂不优先：复杂 learned router。当前 RNNoise/noisy oracle 相对 noisy 只有 `0.86 pp` 的理论
WER 改善，实际 router 还会引入误路由、双路 ASR 和延迟成本；只有更换增强器/ASR 后 oracle
空间显著增大时才重新评估。
