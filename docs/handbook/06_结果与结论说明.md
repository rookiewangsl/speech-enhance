# 结果与结论说明

最后核验：2026-07-31

本文是项目**当前冻结结果的唯一数字来源**。其他文档负责解释模块、算法和实验过程；如果
历史日志中的阶段性结论与本文冲突，以本文及其列出的冻结 JSON/CSV 为准。

## 1. 一句话结论

项目已经实现一个可因果流式运行的单通道语音增强前端。当前默认方法是
**R3 official pretrained RNNoise**：它能够去除关键样本中的结构化金属摩擦噪声，支持
16/48 kHz 输入和任意 chunk，但在部分语音上仍有 over-suppression，表现为轻微断续。

完整配对数据上，R3 的 mean SI-SDRi 为：

- dev 393 条：`+2.614 dB`；
- holdout 431 条：`+4.637 dB`。

但 R3 的 mean ΔSTOI 分别为 `-0.0242` 和 `-0.0407`，不能声称它在总体上提高了语音
可懂度。R4 虽然改善了部分全局客观指标，却把原始金属噪声重新混回；C1 没有在 30 条
dev smoke 上超过 R3。因此 R3 是当前听感选出的基线，不是没有缺陷的最终最优解。

### 2.1 两条运行路径

16 kHz 文件链路：

```text
16 kHz noisy
→ stateful 3× upsampling
→ 48 kHz RNNoise persistent C state
→ stateful 3× downsampling
→ 16 kHz enhanced
```

MacBook 麦克风原生链路：

```text
48 kHz microphone blocks
→ RNNoise persistent C state
→ 48 kHz enhanced recording
```

离线配对评价会按固定延迟对齐 clean/noisy/output；实时系统不能消除物理延迟，只能向下游

## 9. 实时性、延迟和数值安全

### 9.1 固定算法延迟

16 kHz 文件/流式链路：

| 组成 | 16 kHz 等效 |
|---|---:|
| RNNoise 一帧延迟 | `160 samples / 10 ms` |
| 两段状态化 FIR 群延迟 | `42 samples / 2.625 ms` |
| 总固定延迟 | `202 samples / 12.625 ms` |

原生 48 kHz 麦克风链路不经过 16↔48 kHz FIR，因此固定算法延迟约为 RNNoise 的一帧，
即 10 ms。真实端到端麦克风延迟还包含 CoreAudio buffer、线程调度、队列和下游模块，
不能只用 10 ms 代表完整设备体验。

### 9.2 RTF

完整 393 条 dev 的 R3 processing-only：

- mean RTF：`0.0573`；
- median RTF：`0.0483`。

RTF 定义为：

```math
\mathrm{RTF}=\frac{\text{processing time}}{\text{audio duration}}
```

RTF `< 1` 表示平均处理速度快于音频实时播放速度。本次结果支持“当前机器上能够实时运行”，
但不能证明所有硬件、所有系统负载或每个 callback 都绝不超时。RTF 会随 CPU、编译选项、
后台负载和测量范围变化。

固定 `p232_005` 一键 demo 的一次 processing RTF 为 `0.0149`，仅是单次样本报告，不用作
跨硬件 headline。

### 9.3 Clipping

直接核对 per-file CSV：

- R3/R4 dev 393 条：所有方法 clipping samples 合计为 0；
- R3/R4 holdout 431 条：所有方法 clipping samples 合计为 0；
- R3/C1 dev 30 条：所有方法 clipping samples 合计为 0；
- R3 16 kHz full-dev 的 resampler-input clipping samples 合计为 0。

clipping 为 0 只能证明幅值没有越界，不代表没有听感失真、吞字或金属伪影。

### 9.4 延迟错误的负对照

早期只补偿 42-sample FIR delay，遗漏 RNNoise 的 160 samples，导致 30 条 dev mean
SI-SDRi 为 `-28.109 dB` 且全部为负。补偿完整 202 samples 后，
`p232_005` 恢复到 `+7.209 dB`。

这个结果说明 SI-SDR 对固定时间错位非常敏感；离线评价必须对齐，但实时系统不能声称通过
裁剪输出“消灭了”物理延迟。

### 为什么 R4 指标更好却不能采用

R4 混回 noisy 后，确实可能恢复 R3 误删的语音，从而改善 STOI 和部分 SI-SDR 分布；
但同一 residual 也包含 R3 正确删除的结构化金属噪声。全局均值没有充分惩罚局部短时但
非常显著的噪声伪影。因此固定样本人工试听推翻了只依据客观指标做出的选择。

## 11. 指标含义与边界

### 11.1 SI-SDR 与 SI-SDRi

SI-SDR 衡量参考 clean 与估计语音之间，在允许整体缩放后的目标能量/误差能量比，单位为
dB，通常越大越好。

```math
\mathrm{SI\mbox{-}SDRi}
=\mathrm{SI\mbox{-}SDR}_{output}
-\mathrm{SI\mbox{-}SDR}_{input}
```

- SI-SDRi `> 0`：输出比原 noisy 更接近 clean；
- scale-invariant 不等于 delay-invariant，固定错位会严重破坏数值；
- 它是全局波形指标，可能掩盖局部金属声、泵动或短音素损伤；
- 必须有时间对齐的 clean reference，真实麦克风录音通常无法计算。

### 11.2 STOI 与 ΔSTOI

STOI 估计短时语音可懂度，常见范围约为 0～1，越高通常表示可懂度越好。

```math
\Delta\mathrm{STOI}
=\mathrm{STOI}_{output}
-\mathrm{STOI}_{input}
```

- ΔSTOI `> 0`：相对输入的预测可懂度提高；
- ΔSTOI `< 0`：增强可能伤害可懂度相关信息；
- STOI 不是完整主观音质指标，不能充分描述金属感、自然度和听觉舒适度；
- R3 dev/holdout mean ΔSTOI 为负，是本项目必须公开的限制。

### 11.3 Precision、Recall、F1

对 VAD：

```math
\mathrm{Precision}=\frac{TP}{TP+FP}
```

表示预测为语音的帧中有多少是真的语音。

```math
\mathrm{Recall}=\frac{TP}{TP+FN}
```

表示真实语音帧中有多少被找到。

```math
\mathrm{F1}
=2\frac{\mathrm{Precision}\cdot\mathrm{Recall}}
{\mathrm{Precision}+\mathrm{Recall}}
```

F1 是 precision 与 recall 的调和平均。它不能单独体现误报发生在什么噪声类型或时间位置。

### 11.4 FAR 与 miss rate

```math
\mathrm{FAR}=\frac{FP}{FP+TN}
```

FAR 表示真实非语音帧被误报成语音的比例，越低越好。

```math
\mathrm{Miss\ Rate}=\frac{FN}{FN+TP}=1-\mathrm{Recall}
```

实际系统中，低 FAR 与低 miss 往往互相制约，应依据降噪、唤醒或端点检测任务选择阈值。

### 11.5 Positive fraction 与 nonnegative fraction

- Positive SI-SDRi fraction：SI-SDRi `> 0` 的文件比例；
- Nonnegative ΔSTOI fraction：ΔSTOI `≥ 0` 的文件比例。

它们用于观察结果稳定性，防止均值被少量大幅成功样本主导，但仍不能代替逐噪声类型和人工
试听分析。

### 11.6 RTF、algorithmic delay、clipping 与 peak

- RTF：处理时间/音频时长，越低越快；
- algorithmic delay：算法必须等待的固定历史或 look-ahead；
- clipping samples：绝对幅值超过允许范围的样本数；
- peak：输出最大绝对幅值。

四者分别描述吞吐、因果延迟和数值安全，不直接衡量降噪质量。

## 12. 当前最终选择

### 12.1 默认方案

**R3 official pretrained RNNoise**。

采用它的理由：

1. 能稳定去除固定失败样本中的结构化金属噪声；
2. 支持 persistent state 和任意 chunk 的因果流式处理；
3. 16 kHz 路径固定延迟为 12.625 ms，平均 RTF 明显小于 1；
4. 完整 dev/holdout 的 mean SI-SDRi 均为正；
5. R4/C1 尚未同时通过客观和主观门槛。

### 12.2 必须同时说明的缺陷

1. R3 在部分语音上存在 over-suppression/断续；
2. dev/holdout mean ΔSTOI 均为负；
3. 不是所有文件都受益：positive SI-SDRi 分别为 `72.01%/78.19%`；
4. 系统只覆盖单通道 noise suppression，不包含 AEC、beamforming、dereverberation；
5. 当前配对数据与真实 MacBook 麦克风之间存在 domain gap。

### 12.3 被否决但保留的方案

- R4 conservative/aggressive：客观消融结果完整，但固定试听失败；
- R4 80/20、90/10：只用于证明少量 broadband residual 仍恢复结构噪声；
- C1 3 dB：仅保留试听和面试中的负结果分析；
- C1 6 dB：客观 smoke 直接淘汰；
- A8 IMCRA + OM-LSA：证明更复杂统计 estimator 不一定能处理结构噪声。

## 13. 可以和不可以得出的结论

### 可以说

- 实现并工程化了 official pretrained RNNoise 实时单通道增强链；
- 自主实现了经典 VAD、noise PSD、Wiener/OM-LSA、流式 FIR、指标和测试链；
- 在内部 speaker-disjoint 的 393/431 对数据上完成冻结消融；
- R3 的 mean SI-SDRi 为 `+2.614/+4.637 dB`；
- 定位了 12.625 ms 固定延迟和 noise PSD 低估问题；
- 通过试听发现并否决了客观指标更好的 residual mixing；
- 当前系统能实时运行，但仍存在语音断续和负 mean ΔSTOI。

### 不可以说

- 这些数字是 VoiceBank + DEMAND 官方 benchmark 排名；
- RNNoise 网络和预训练权重由本项目设计或训练；
- R3 在所有样本上都改善；
- R3 整体提高 STOI/可懂度；
- R4 是最终效果最好方案；
- clipping 为 0 就等于没有失真；
- 10/12.625 ms 是完整产品端到端延迟；
- 一个 `p232_005` 的成功代表全部噪声类型。
