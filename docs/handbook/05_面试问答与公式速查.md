# 面试问答与公式速查

最后更新：2026-08-14

## 1. 一分钟项目介绍

> 我实现了一个可实时流式运行的单通道语音增强前端。经典路线是 MCRA 加
> decision-directed Wiener，学习路线使用 official pretrained RNNoise；我没有训练 RNNoise，
> 主要工作是 persistent C state、任意 chunk、16/48 kHz 状态化重采样、固定延迟、数据审计、
> 条件化评测和失败定位。8-speaker validation 表明 RNNoise 在低 SNR 抑制更强，但 high-SNR
> 和 babble 会过处理；固定 Whisper 的 100 条初步实验还表明 RNNoise 可能显著损害 WER。
> 因此项目的核心结论是：感知增强和机器识别目标不等价，前端必须按场景和下游任务验证。

## 2. 高频问答

### Q1：哪些是你的贡献，哪些来自开源？

RNNoise 网络、特征、权重和 C core 属于 Xiph；Whisper 属于 OpenAI；MCRA/Wiener 是经典
算法。本项目贡献是独立经典实现、实时适配、数据和延迟协议、自动测试、完整评测、消融和
ASR 影响分析。

### Q2：为什么同时保留 Wiener 和 RNNoise？

RNNoise 平均抑制更强，适合低 SNR 和默认听感 Demo；DD-Wiener 抑制较弱但更保守，在
high-SNR 和 babble 下更稳定。二者代表不同工程折中，不是简单的旧算法和新算法排名。

### Q3：RNNoise 是端到端生成波形吗？

不是。DSP 提取 32-band 能量和 pitch 特征，网络预测 32 个 band gains 与一个 VAD probability，
再由 pitch filtering、频域增益、iFFT 和 overlap-add 重建波形。

### Q4：65 维输入是什么？

32 维谱包络 cepstrum、32 维 pitch correlation cepstrum 和 1 维 pitch period。它们结合谱形、
周期性和跨帧 GRU 状态判断语音与噪声。

### Q5：为什么 state 必须持久化？

state 保存 Conv/GRU、pitch、overlap、delayed spectrum 和历史 gain。每帧重建会丢失时序、
破坏合成连续性并改变算法输出，不只是速度变慢。

### Q6：如何支持任意 chunk？

外部 chunk 先进入 buffer，凑满 480 个 48 kHz samples 才调用同一个 RNNoise state；尾部由
`flush()` 处理。整段输入和任意切块输入必须逐样本一致。

### Q7：为什么需要 16→48→16 kHz？

VoiceBank/Whisper 使用 16 kHz，official RNNoise 固定为 48 kHz。本项目用 127-tap 状态化
Kaiser FIR 做 3× 上下采样，不能对每个 chunk 独立调用离线 resampler，否则相位和边界变化。

### Q8：12.625 ms 延迟怎么得到？

RNNoise core 一帧为 `160 samples@16k=10 ms`，两段 FIR 共 `42 samples=2.625 ms`，总计
`202 samples=12.625 ms`。离线指标可以对齐补偿，实时因果延迟不能消失。

### Q9：为什么早期 SI-SDRi 会是 -28 dB？

当时只补偿 FIR 的 42 samples，漏掉 RNNoise 的一帧 160 samples。clean/enhanced 错位导致
逐样本指标崩溃；补齐 202 samples 后恢复正常。

### Q10：关键金属声是 musical noise 吗？

主要不是。`noisy-clean` 残差证明它本来就存在于输入，是高能结构噪声；经典 estimator 把它
误保护。Oracle Wiener 能去除它，说明瓶颈在 noise PSD/SPP 估计，不在 STFT/WOLA 表达能力。

### Q11：为什么 R4 指标更好却被淘汰？

R4 混回 noisy 后 STOI 改善，但也把关键金属结构噪声混回。全局均值没有充分惩罚局部强烈
缺陷，所以固定试听推翻了单指标选择。

### Q12：C1 为什么不能恢复吞掉的语音？

C1 只放大 RNNoise 输出中仍存在的内容。音素如果已被删除，output-only gain 无法重建；
残留若是噪声还可能产生 pumping。

### Q13：为什么增强后听起来更干净，ASR 反而更差？

ASR 能容忍部分自然噪声，却可能对不自然的增强伪影、辅音删除和共振峰过渡破坏更敏感。
感知质量、SI-SDR/STOI 和 WER 的优化目标不同。

### Q14：Whisper 为什么会产生大量重复 insertion？

目标语音被过度抑制后，encoder 的声学约束变弱；自回归 decoder 一旦进入高概率重复前缀，
后续更受自身文本历史驱动。输出接近 token limit，额外词在 WER 对齐中成为 insertion。

### Q15：temperature retry 是否保证更正确？

不保证。它可以离开某个重复循环，但新的流畅短句仍可能语义错误。v2 因此还比较重试与 paired
noisy hypothesis 的词距离，并在不一致时回退 noisy。

### Q16：reference oracle 是 clean ASR 吗？

不是。它用人工 transcript 逐条比较 RNNoise ASR 和 noisy ASR 的错误数，事后选择较小者。
它衡量理想路由上限，但真实运行没有答案，所以不可部署。

### Q17：为什么 v2 从 40.99% 降到 14.11% 仍不算成功？

因为 noisy 只有 5.65%。v2 修复了两个灾难样本，却漏掉多数“文本形态正常但语义更差”的
RNNoise 输出；detector 对 harmful 样本 recall 只有 7.41%。

### Q18：当前结果是不是只有 100 条？

只有 ASR 是 100 个 utterance、四路 400 输入；增强评测已经完成 validation 3,224 对和
official test 824 对。ASR 全量 12,396 个 utterance 尚未运行。

### Q19：全量为什么先 development 再 validation？

Development 用于诊断和创建新版本，validation 是冻结后的未见 speaker 确认。看过 validation
后不能继续调阈值再覆盖同名结果。official test 只作补充，因为历史接触过。

### Q20：工业 ASR 什么时候加前端？

适合 AEC reference、多麦阵列、远场、稳定机械噪声、端点和 raw ASR 明显失败的场景；不适合
high-SNR、单通道 babble、目标说话人不明确或只凭听感开启激进抑制。最终标准是 paired WER。

## 3. 公式速查

### STFT

```math
X(k,m)=\sum_n x[n]w[n-mH]e^{-j2\pi kn/N}
```

`N` 为 FFT length，`H` 为 hop。WOLA 用对应合成窗和 overlap-add 重建。

### A posteriori / priori SNR

```math
\gamma(k,m)=\frac{|X(k,m)|^2}{\lambda_N(k,m)},\qquad
\xi(k,m)=\frac{\lambda_S(k,m)}{\lambda_N(k,m)}
```

### Wiener gain

```math
G(k,m)=\frac{\xi(k,m)}{1+\xi(k,m)}
```

### SI-SDR improvement

```math
\mathrm{SI\!\!-\!SDRi}
=\mathrm{SI\!\!-\!SDR}(\hat{s},s)
-\mathrm{SI\!\!-\!SDR}(y,s)
```

正值表示 enhanced 相对 noisy 改善，但对延迟错位非常敏感。

### ΔSTOI

```math
\Delta\mathrm{STOI}=\mathrm{STOI}(\hat{s},s)-\mathrm{STOI}(y,s)
```

它近似可懂度，不能充分衡量自然度、金属声或局部吞字。

### WER

```math
\mathrm{WER}=\frac{S+D+I}{N}
```

主结果使用 corpus WER：先汇总所有 S/D/I/N，再计算比例，不对逐句 WER 做简单平均。

### RTF

```math
\mathrm{RTF}=\frac{\text{processing seconds}}{\text{audio seconds}}
```

`RTF<1` 只表示平均算力足够，不保证每个 callback deadline 都满足。

### Precision / Recall

```math
\mathrm{Precision}=\frac{TP}{TP+FP},\qquad
\mathrm{Recall}=\frac{TP}{TP+FN}
```

v2 detector 当前高 precision、低 recall：报警通常真实，但漏掉多数普通语义退化。

## 4. 表达红线

不要说：

- “我训练或设计了 RNNoise 网络”；
- “MCRA/Wiener 是我的算法创新”；
- “RNNoise 全场景提高可懂度或 ASR”；
- “official test 是完全盲测”；
- “100 条 ASR 已代表全部 12,396 条”；
- “v2 已达到工业最优”；
- “clean ASR 输出是 WER reference”。

建议说：

> 我把官方预训练模型工程化为可验证的实时前端，并通过完整数据、失败样本、感知指标和固定
> ASR 揭示它的收益与边界；当前证据支持条件化使用，而不是无条件串接。
