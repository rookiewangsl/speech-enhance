# 数据集说明

最后更新：2026-07-31

本文说明项目使用了什么数据、数据怎样进入实验、如何避免明显的数据泄漏，以及结果能够
说明什么、不能说明什么。最终数值结果统一见
[06_结果与结论说明.md](06_结果与结论说明.md)，本文不重复维护指标表。

## 1. 数据在项目中的用途

项目有两套相关但用途不同的数据：

| 数据 | 用途 | 是否有 clean reference | 是否有逐帧 VAD 标签 |
|---|---|---:|---:|
| VoiceBank + DEMAND 官方 test pairs | 语音增强的客观评价、调参和固定试听 | 有 | 无 |
| 项目生成的受控 VAD mixtures | Energy、Statistical、WebRTC VAD 对比 | 有 | 有，来自插入区间 |

二者不能混为一谈：

- 增强实验使用完整的自然语句 clean/noisy pair；
- VAD实验为了得到可靠的语音起止标签，重新构造“噪声轨道＋随机语音片段”；
- MacBook麦克风录音没有clean reference，只做实时性检查和人工A/B试听，不能计算
  SI-SDR或STOI。

## 2. 主数据：VoiceBank + DEMAND test pairs

### 2.1 来源

项目只下载University of Edinburgh发布页面中的两份官方test-pair压缩包：

- [VoiceBank + DEMAND官方页面](https://datashare.ed.ac.uk/handle/10283/2791)
- `clean_testset_wav.zip`：clean reference；
- `noisy_testset_wav.zip`：与clean同名、同长度的noisy observation。

下载配置记录在
[`configs/data_sources.json`](../../configs/data_sources.json)，下载脚本为
[`scripts/download_voicebank.py`](../../scripts/download_voicebank.py)。

为避免下载损坏或上游内容变化，项目记录了以下SHA-256：

| 文件 | WAV数量 | SHA-256 |
|---|---:|---|
| `clean_testset_wav.zip` | 824 | `b60bfc2b9df38466d8eb45057c087c6e5dee196c67a0ed7bca628ae2a8611c4e` |
| `noisy_testset_wav.zip` | 824 | `ba4a893f45b627f15209ba30ab584dd495b3680cd6f216dd08d143a257611993` |

原始WAV为48 kHz、单声道、PCM 16-bit。clean与noisy通过文件名stem配对，例如：

```text
clean_testset_wav/p232_001.wav
noisy_testset_wav/p232_001.wav
```

项目没有下载约5 GB的28-speaker训练子集，也没有使用这824对音频训练RNNoise。RNNoise
使用的是官方预训练网络。

### 2.2 当前实际组成

两个压缩包各有824条WAV，文件名包含两个speaker：

| Speaker | 内部用途 | Pair数量 |
|---|---|---:|
| `p232` | dev | 393 |
| `p257` | holdout | 431 |
| 合计 |  | 824 |

manifest中的每一行记录：

```json
{
  "id": "p232_001",
  "speaker_id": "p232",
  "clean": "data/processed/voicebank/clean/p232_001.wav",
  "noisy": "data/processed/voicebank/noisy/p232_001.wav",
  "sample_rate": 16000,
  "num_samples": 27861,
  "split": "dev"
}
```

当前manifest没有保存`noise_type`和原始混合`snr_db`，所以现有正式结果不能按噪声类别
或官方SNR条件分组。若以后需要这种分析，必须先从可信元数据建立映射，不能从音频ID猜测。

## 3. 内部speaker-disjoint划分

### 3.1 划分方法

[`split_pairs_by_speaker`](../../src/speech_frontend/dataset.py)先从文件名中提取speaker
前缀，再对speaker列表进行确定性打乱：

```text
dev_fraction = 0.4
seed = 20260724
```

当前只有两个speaker，因此实际得到：

```text
p232：393对 → dev
p257：431对 → holdout
```

两个集合没有说话人重叠。参数选择、阈值调整和路线筛选只允许使用dev；方案冻结后才在
holdout上运行。

### 3.2 必须保留的结论边界

这不是VoiceBank + DEMAND官方benchmark protocol，而是项目为了在只有官方test pairs的
条件下建立的内部speaker-disjoint验证协议。因此：

- 可以比较本项目各条路线在同一协议下的相对差异；
- 可以验证代码、流式链路、延迟对齐和跨说话人稳定性；
- 不能把这些数字与采用官方train/test protocol的论文做排行榜式比较；
- dev与holdout都来自官方test set，不能把holdout称为官方test benchmark；
- 简历和面试中应始终说“内部speaker-disjoint holdout”。

## 4. VoiceBank pair预处理

处理入口为
[`scripts/prepare_voicebank.py`](../../scripts/prepare_voicebank.py)，核心实现位于
[`src/speech_frontend/dataset.py`](../../src/speech_frontend/dataset.py)和
[`src/speech_frontend/audio.py`](../../src/speech_frontend/audio.py)。

### 4.1 处理流程

```text
下载两份ZIP
→ 安全解压WAV
→ 按文件名stem发现clean/noisy pair
→ 检查原始pair采样率和长度一致
→ clean/noisy使用相同的48→16 kHz polyphase参数
→ 再次检查输出pair采样率和长度一致
→ 写入float WAV
→ 生成dev.jsonl和holdout.jsonl
```

### 4.2 安全解压

`safe_extract_wav_zip`不是直接信任压缩包，而是：

- 只接受`.wav`文件；
- 拒绝绝对路径、`..`路径穿越和符号链接；
- 默认最多20,000个文件、解压后最多20 GiB；
- 先写入`.part`目录，成功后再原子替换目标目录。

### 4.3 配对和输入契约

`discover_voicebank_pairs`要求：

- clean和noisy的文件名stem集合完全一致；
- 不允许同一目录出现重复stem；
- 文件名必须能解析出`speaker_id`；
- 每个pair在处理前满足相同采样率、相同shape。

项目内部音频契约为：

- 一维单声道数组；
- 浮点dtype；
- 所有样本为有限值，不允许NaN或Inf；
- 不在读取阶段自动归一化幅值。

这里没有“立体声自动转单声道”的规则。多声道输入会被拒绝，以避免左右声道采用了一个
未记录的混合策略。

### 4.4 48→16 kHz重采样

预处理使用`scipy.signal.resample_poly`。对于48→16 kHz：

```text
up = 1
down = 3
```

clean和noisy分别执行重采样，但使用完全相同的`up/down`和默认滤波设置；输出转为
`float32`。重采样后再次调用`validate_aligned_pair`，保证二者长度仍一致。

项目不对clean和noisy分别做peak normalization，也不分别调整响度。原因是独立归一化会
破坏二者原有的共同尺度，使：

```text
true_noise = noisy - clean
```

不再具有正确物理意义，并污染SI-SDR、Oracle和残差诊断。

处理后的WAV使用`subtype="FLOAT"`保存，目录为：

```text
data/processed/voicebank/clean/
data/processed/voicebank/noisy/
```

### 4.5 manifest与可复现性

manifest使用JSONL，每行一条记录，路径相对于项目根目录。写入采用`.part`临时文件后
原子替换，避免中断后留下半份manifest：

```text
data/manifests/dev.jsonl       # 393行
data/manifests/holdout.jsonl   # 431行
```

`num_samples`允许在不打开音频的情况下检查样本长度；真正评价前仍会重新读取音频并检查
pair对齐。

## 5. 受控VAD数据

### 5.1 为什么另外生成

VoiceBank pair没有项目所需的逐sample语音活动标签。若用待评测的Energy VAD生成“标签”，
再评价Energy VAD，会形成循环验证。

因此项目使用
[`scripts/build_vad_dataset.py`](../../scripts/build_vad_dataset.py)和
[`src/speech_frontend/vad/synthetic.py`](../../src/speech_frontend/vad/synthetic.py)
生成可控mixture，ground truth直接来自语音被插入的sample interval。

### 5.2 当前数据规模

| 数据 | 来源manifest | 数量 | 单条时长 | 采样率 |
|---|---|---:|---:|---:|
| `vad_dev100` | `p232` dev | 100 | 10 s | 16 kHz |
| `vad_holdout100` | `p257` holdout | 100 | 10 s | 16 kHz |

此外保留20+20条早期smoke数据，但正式VAD选择使用100+100条。

### 5.3 生成方法

对每个来源partition：

1. 读取所有clean/noisy pair并再次验证对齐；
2. 将clean语音加入`speech_pool`；
3. 使用`noisy - clean`构造`residual_pool`；
4. 创建10秒全零clean track；
5. 随机插入1～4段语音，每段0.5～2.0秒；
6. 相邻语音段之间保留0.3～2.0秒gap；
7. 从residual pool随机取片段、循环移位并拼接成10秒noise track；
8. 去除noise track的直流均值；
9. 按活跃语音样本计算功率，把噪声缩放到指定SNR；
10. 合成`noisy = clean + scaled_noise`；
11. 若峰值超过0.98，对clean和noisy施加同一个common gain；
12. 保存clean、noisy、SNR和精确的`speech_intervals`。

SNR按以下序列循环：

```text
-5, 0, 5, 10, 15 dB
```

默认随机seed为`20260724`。标签单位是sample index，例如：

```json
{
  "id": "mix_000000",
  "sample_rate": 16000,
  "snr_db": -5.0,
  "speech_intervals": [[4845, 18599], [46309, 77969]]
}
```

评价时再根据frame length和hop length把sample interval投影为frame label。

### 5.4 VAD协议的边界

这套数据的优点是标签精确、SNR可控、dev/holdout来源说话人隔离；局限是：

- 语音片段是人工插入，停顿和上下文不完全等同于连续真实对话；
- noise由`noisy-clean`残差拼接得到，不等同于独立录制的纯噪声库；
- 只有两个来源speaker；
- 结果是项目内部controlled protocol，不是公开VAD benchmark；
- 不能据此宣称某个VAD普遍优于WebRTC VAD。

## 6. 数据泄漏控制

项目采用以下约束：

1. **按speaker划分，而不是按utterance随机划分。** 同一说话人的音色不会同时进入dev和
   holdout。
2. **VAD source pool同样隔离。** `vad_dev100`只从`p232`构造，
   `vad_holdout100`只从`p257`构造。
3. **只在dev选参数。** Statistical VAD阈值、WebRTC aggressiveness及增强controller
   候选先在dev决定，再冻结到holdout。
4. **固定试听集不能替代holdout。** 单条`p232_005`用于定位金属结构噪声，不代表总体。
5. **记录外部模型边界。** RNNoise权重由上游预训练，本项目无法控制或完全审计其训练集，
   因而结果定位为预训练模型复现与工程评估，而非从零训练的独立benchmark。

仍然存在的限制是：项目只有两个speaker，speaker-disjoint并不等于足够广泛的说话人、
语言、设备和声学环境泛化。

## 7. 复现路径

在项目根目录运行：

```bash
# 1. 下载两份官方test archives，并打印大小和SHA-256
./.venv/bin/python scripts/download_voicebank.py --data-root data

# 2. 先做每个split 5条的smoke preparation
./.venv/bin/python scripts/prepare_voicebank.py \
  --data-root data \
  --limit-per-split 5

# 3. smoke通过后生成完整824对和正式manifest
./.venv/bin/python scripts/prepare_voicebank.py --data-root data
```

构造VAD数据时分别使用两个speaker partition：

```bash
./.venv/bin/python scripts/build_vad_dataset.py \
  --manifest data/manifests/dev.jsonl \
  --output-root data/processed/vad_dev100 \
  --num-items 100 \
  --duration-seconds 10 \
  --seed 20260724

./.venv/bin/python scripts/build_vad_dataset.py \
  --manifest data/manifests/holdout.jsonl \
  --output-root data/processed/vad_holdout100 \
  --num-items 100 \
  --duration-seconds 10 \
  --seed 20260724
```

核验重点：

```text
dev.jsonl       = 393行，只含p232
holdout.jsonl   = 431行，只含p257
所有processed pair = 16 kHz、mono、同长度
所有VAD mixture = 160000 samples
clean/noisy均无NaN、Inf
```

原始压缩包、解压音频、processed WAV和大部分实验输出不提交Git；下载URL、checksum、
脚本、配置和正式manifest进入版本管理。

## 8. 面试速记

可以用下面这段话说明数据协议：

> 我使用VoiceBank + DEMAND官方test-pair压缩包，共824对48 kHz单声道clean/noisy
> 音频，按文件名配对后用相同polyphase参数降采样到16 kHz，不对两路独立归一化。
> 因为手头没有官方train split，我按speaker建立内部dev/holdout：p232的393对用于选参，
> p257的431对只做冻结评估。这个划分不是官方benchmark，所以我只用它比较项目内方法。
> VAD没有现成逐帧标签，我又从两个partition分别生成100条十秒受控mixture，用实际插入
> 区间作为标签，保持来源speaker隔离。
