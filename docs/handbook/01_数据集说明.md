# 数据集说明

最后更新：2026-08-09

本文记录完整 VoiceBank + DEMAND 数据的来源、校验、预处理、speaker 划分和数据边界。结果
统一见[06_结果与结论说明.md](06_结果与结论说明.md)。

## 1. 数据用途与规模

| 数据 | Speaker | Clean/noisy pairs | 时长 | 用途 |
|---|---:|---:|---:|---|
| 官方 28-speaker train | 28 | 11,572 | 9.39 h（16 kHz 后） | development/validation 划分 |
| 官方 test | 2 | 824 | 0.58 h（16 kHz 后） | 冻结方案的补充评估与固定试听 |
| 受控 VAD development | 来源 20 speakers | 100×10 s | 0.28 h | VAD 选参 |
| 受控 VAD validation | 来源 8 speakers | 40×10 s | 0.11 h | VAD 冻结验证 |

RNNoise 使用上游官方预训练权重，项目没有用这些数据重新训练网络。新增的 28-speaker 数据
用于扩大 speaker 覆盖、重新选择 VAD/经典基线参数、验证 RNNoise 泛化和按噪声条件分析。

训练集下载使用 HTTP Range 分段传输；组装时先核对总字节数，再遍历 ZIP 内所有成员做 CRC

后删除；最终 ZIP、解压 WAV 和处理后数据保留。

## 3. 官方混合条件

`logfiles.zip` 为每条音频提供 `noise` 和 `snr_db`，预处理时直接写入 manifest，不能根据
文件编号猜测。

28-speaker train 包含 10 类噪声：

```text
babble, cafeteria, car, kitchen, meeting,
metro, restaurant, ssn, station, traffic
```

SNR 为 `0/5/10/15 dB`。官方 test 包含 `bus/cafe/living/office/psquare`，SNR 为
`2.5/7.5/12.5/17.5 dB`。这使项目能观察总体均值之外的失败条件。

## 4. 20/8/2 speaker 协议

`split_pairs_by_speaker_count` 对 28 个训练 speaker 使用固定 seed `20260724` 打乱，精确分成
20-speaker development 和 8-speaker validation；官方 test 两个 speaker 单列：

| Partition | Pairs | Speakers | 时长 |
|---|---:|---:|---:|
| development | 8,348 | 20 | 6.688 h |
| validation | 3,224 | 8 | 2.703 h |
| official_test | 824 | 2 | 0.576 h |

Development speakers：

```text
p227 p228 p230 p231 p236 p239 p243 p244 p250 p254
p267 p268 p270 p273 p274 p277 p278 p279 p282 p287
```

Validation speakers：

```text
p226 p233 p256 p258 p259 p269 p276 p286
```

Official test speakers：`p232 p257`。

审计报告 `outputs/full_protocol/data_audit.json` 已确认：12,396 个总 pair、30 个 speaker，
三个 partition 之间 speaker 和 utterance 都不重叠，所有记录为 16 kHz 且音频路径存在。

### 历史使用边界

虽然当前代码和本轮流程把 official test 单独隔离，项目早期曾把这 824 对数据划成
`p232 dev / p257 holdout`，并多次使用 `p232_005` 试听选路线。因此 official test 已有历史
开发接触，不能包装成完全盲测的论文级 test。当前官方 test 数字用于补充描述和与旧结果
衔接；更可信的未见 speaker 结论来自 8-speaker validation。

## 5. 48→16 kHz 成对预处理

入口为[`scripts/prepare_voicebank.py`](../../scripts/prepare_voicebank.py)，核心位于
[`src/speech_frontend/dataset.py`](../../src/speech_frontend/dataset.py)。

```text
校验 ZIP
→ 安全解压 WAV
→ 按 filename stem 配对 clean/noisy
→ 检查原始采样率、shape 和长度一致
→ 使用相同 polyphase 参数 48→16 kHz
→ 再次检查输出对齐
→ 写 float WAV
→ 合并官方 noise/SNR 日志
→ 原子写入 JSONL manifest
```

关键约束：

- 只接受单声道有限值音频，不隐式做 stereo downmix；
- clean/noisy 不分别做 peak normalization，避免破坏 `noise = noisy - clean`；
- `scipy.signal.resample_poly` 对两路使用相同 `up=1/down=3`；
- 4 个 worker 只并行独立 pair，`executor.map` 保持 manifest 顺序；
- 安全解压拒绝绝对路径、`..`、符号链接和非 WAV 成员，并通过临时目录原子替换。

处理后目录：

```text
data/processed/voicebank/clean/
data/processed/voicebank/noisy/
```

Manifest：

```text
data/manifests/development.jsonl            # 8348
data/manifests/validation.jsonl             # 3224
data/manifests/official_test.jsonl           # 824
data/manifests/development_balanced_5.jsonl # 20×5=100
data/manifests/validation_balanced_5.jsonl  # 8×5=40
```

每行包含 `id/speaker_id/clean/noisy/sample_rate/num_samples/split/source_partition/noise/snr_db`。

## 6. 为什么需要 speaker-balanced 子集

直接使用 `--limit 100` 会从按文件名排序的 manifest 头部取样，样本可能集中在一个 speaker。
[`scripts/sample_manifest_by_speaker.py`](../../scripts/sample_manifest_by_speaker.py)改为每个
speaker 固定抽 5 条：100 条 development 用于快速调参，40 条 validation 用于冻结冒烟。
全量结论仍在 3,224/824 条上计算。

## 7. VAD 控制数据

VoiceBank 没有项目所需的逐 sample 语音活动标签。项目从各 partition 的 clean 语音和
`noisy-clean` 残差构造 10 秒混合：随机插入 1～4 段语音，标签直接取插入 sample interval，
并循环覆盖 `-5/0/5/10/15 dB`。

```text
data/processed/vad_full/development/manifest.jsonl # 100
data/processed/vad_full/validation/manifest.jsonl  # 40
```

Development 与 validation 的 speech/noise source speaker 完全隔离。局限是语音片段和残差
拼接不等同于真实连续通话，因此它是可控内部协议，不是公开 VAD benchmark。

## 8. 复现命令

```bash
# 下载完整 train28；test 和日志同样由配置记录
./.venv/bin/python scripts/download_voicebank.py \
  --data-root data --subset train28

# 完整预处理
./.venv/bin/python scripts/prepare_voicebank.py \
  --data-root data --protocol full28 \
  --development-speakers 20 --seed 20260724 --workers 4

# 数据协议审计
./.venv/bin/python scripts/audit_full_protocol.py \
  --project-root . --manifest-root data/manifests \
  --output outputs/full_protocol/data_audit.json

# 均衡调参子集
./.venv/bin/python scripts/sample_manifest_by_speaker.py \
  --input data/manifests/development.jsonl \
  --output data/manifests/development_balanced_5.jsonl \
  --items-per-speaker 5 --seed 20260724
```

固定协议和参数统一记录在[`configs/full_protocol.json`](../../configs/full_protocol.json)。原始
ZIP、解压 WAV、处理 WAV 和大多数输出不进入 Git；代码、checksum、manifest、冻结配置和
总结文档进入版本管理。

## 9. 面试表述

> 我下载并校验了 VoiceBank+DEMAND 官方 28-speaker train 和 2-speaker test，共 12,396 对
> 48 kHz clean/noisy 音频。两路使用相同 polyphase 参数降到 16 kHz，不独立归一化，并把
> 官方 noise/SNR 日志写入 manifest。28 个训练 speaker 用固定 seed 分成 20 个 development
> 和 8 个未见 speaker validation，官方 test 单列。RNNoise 权重不重训，完整数据用于 VAD、
> 经典基线选参和预训练模型泛化评估。由于项目早期接触过官方 test，最终会主动说明它不是
> 完全盲测，核心泛化证据以 8-speaker validation 为准。
