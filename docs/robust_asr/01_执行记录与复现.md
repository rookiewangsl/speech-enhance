### 4.2 Clean CER 与数字书写形式审计

AISHELL-1 标注使用中文读法，而 Whisper 经常输出阿拉伯数字。例如标注“约为四点八万元”时，
模型可能输出“约为 4.8 万元”。正式 normalizer 按预注册协议保留数字且不做逆文本规范化，因此这会
被计为字符错误。

已在封存 test 转写上完成正式的只读对照重评分，主 CER 完全不变。辅助协议不根据参考答案逐句选读法：
百分数统一为“百分之+数值”，四位年份逐位读取，其余整数采用基数读法，小数采用“整数+点+逐位小数”。
另以“全部逐位读取”做规则敏感性对照，以逐句最优合理读法只做诊断下界。

| 模型/条件 | 主 CER | 固定数字规范化 CER | 差值 |
|---|---:|---:|---:|
| W0 Clean | 14.08% | 10.95% | −3.14 pp |
| W0 Robust Raw | 23.61% | 20.82% | −2.79 pp |
| W0 Robust M-WPE | 15.39% | 12.47% | −2.92 pp |
| Clean-LoRA Clean | 7.76% | 7.76% | 0.00 pp |
| MCT-LoRA Clean | 7.83% | 7.83% | 0.00 pp |
| Paraformer Clean | 2.33% | 2.33% | 0.00 pp |

W0 的 1,000 条 clean 中有 141 条输出阿拉伯数字；固定规则使其中 136 条改善、2 条恶化、3 条不变。
数字输出子集 CER 从 `31.82%` 降到 `11.59%`，无阿拉伯数字输出的控制子集保持 `10.83%`。相反，
Clean-LoRA、MCT-LoRA 和 Paraformer 的 clean 输出均没有阿拉伯数字，说明 Clean-LoRA 同时学习了
AISHELL 的中文数字书写风格。

数字规范化后，W0→Clean-LoRA 的 clean 收益由 `−6.32 pp` 变为 `−3.18 pp`
（95% CI `[−3.75,−2.62] pp`），仍显著但不能再把全部主 CER 收益解释为声学/语言能力提升。
核心鲁棒性结论不变：W0 的 Robust WPE 收益为 `−8.35 pp`
（`[−9.16,−7.65] pp`），MCT 相对 Clean-LoRA 的 Robust Raw 收益为 `−1.16 pp`
（`[−1.42,−0.91] pp`）。完整协议、四模型结果和复现命令见
`06_数字规范化CER对照实验.md`。

证据文件：`outputs/number_normalization_formal_test_v1.json`、
`outputs/number_normalization_paired_contrasts_v1.json` 和四个
`*.number_normalization_v2.json`；原始 JSONL 未被改写。此前开发集逐句最优读法的 `9.45%`
只是早期诊断，不再作为正式辅助结果。

- clean 输入直接送入 ASR，不经过 WPE；
- M-WPE-10 只作为已知四通道混响输入的实验前端，不宣称可无条件常开；
- 不因这项审计重新搜索 WPE 参数，因为正式问题是混响抑制，且预注册调参触发条件未满足；

### 4.4 Greedy 与 Beam-5 解码敏感性

在同一 100 条配对子集上比较 greedy 与 Beam-5，条件为 clean level、RT60=0.8 s Raw 和

| 条件 | Greedy CER | Beam-5 CER | Beam−Greedy 95% CI |
|---|---:|---:|---:|
| Clean level | 12.06% | 10.62% | `[-2.49,-0.56] pp` |

| M-WPE-10，RT60=0.8 s | 13.85% | 12.92% | `[-2.14,+0.22] pp` |

Beam-5 对 clean 子集的绝对 CER 改善显著；两个混响条件的点估计也更低，但区间跨零。Beam-5 下

推翻前端方向。主实验继续统一使用 greedy，原因是它已经用于冻结 W0 全矩阵，且计算量更低、跨模型
和跨 checkpoint 更容易严格对齐；Beam-5 只允许在最终最佳模型上另行报告，不能与 greedy 主表混用。

证据文件：`outputs/whisper_decode_beam5_dev_100utt_v1.jsonl`、同名 `.summary.json` 与
`.comparison.json`；Beam-5 run protocol SHA-256 为
`f8b84c5c0e83023ca0a427e0946864db736b7899d938f23da21adc72434b455d`。

### 4.5 信号指标与 CER 是否一致

使用与正式 WPE 开发集完全相同的 500 条语音、五档 RT60 和四个前端，计算 10,000 条信号指标。
参考目标不是原始 clean 直接裁齐，而是同一四通道 RIR 文件中的 `direct` 响应在 reference channel
上的卷积结果；这样保留传播时延，并把晚期反射视为待抑制成分。指标为零均值 SI-SDR 和 classical
STOI。RIR 已先通过全文件校验，2,500 个 utterance–RT60 job 使用 32 个进程完成。

M-WPE-10 相对 Raw 的均值变化如下，所有 paired bootstrap 95% CI 都完全高于零：

| RT60 | Raw SI-SDR | M-WPE SI-SDR | ΔSI-SDR | Raw STOI | M-WPE STOI | ΔSTOI |
|---:|---:|---:|---:|---:|---:|---:|
| 0.2 s | −2.69 | −1.60 | +1.09 dB | 0.881 | 0.908 | +0.027 |
| 0.4 s | −7.21 | −4.62 | +2.59 dB | 0.780 | 0.882 | +0.102 |
| 0.6 s | −11.63 | −7.74 | +3.90 dB | 0.668 | 0.835 | +0.166 |
| 0.8 s | −12.73 | −8.38 | +4.35 dB | 0.622 | 0.804 | +0.182 |
| 1.0 s | −12.21 | −7.93 | +4.28 dB | 0.584 | 0.774 | +0.190 |

![WPE 的 CER 与信号指标相对 Raw 变化](../figures/robust_asr_frontend_metric_alignment.png)

总体上，M-WPE 的信号收益和 CER 收益随混响增强而同步扩大，支持它确实抑制了晚期混响。不过信号
指标不能替代 CER：在 RT60=0.4 s，S-WPE-10/40 的 SI-SDR 和 STOI 相对 Raw 都显著提高，但 CER
分别由 15.30% 变为 16.31%/15.86%。这说明可懂度/波形质量指标没有刻画 Whisper 对前端失真的
全部敏感性，前端选型必须以 ASR 指标为准。该结论也解释了为什么项目同时保留信号指标与任务指标，
而不使用 STOI 或 SI-SDR 单独宣称“有利于识别”。

证据文件：`outputs/frontend_signal_metrics_dev_500utt_v1.jsonl` 及同名 `.summary.json`；
run protocol SHA-256 为
`2bc7fd7784d351b7f688811f6a061751cbf8395363d0a02ecbb398ec872b53f6`。

## 6. LoRA 位置消融与正式训练

先在同一 5 小时 MCT 子集上各训练 500 optimizer steps，只改变 LoRA 的目标位置。
两组均使用 Q/V projection、`r=8` 和相同解码/开发集协议：

| LoRA 位置 | 可训练参数 | Clean CER | Reverb CER | Heavy CER |
|---|---:|---:|---:|---:|
| Encoder Q/V | 294,912（0.122%） | 8.65% | 15.08% | 18.00% |
| Encoder+Decoder Q/V | 884,736（0.365%） | **7.87%** | **13.98%** | **16.78%** |

Encoder+Decoder 在此短程消融中将 Reverb CER 降低 1.10 pp，因此锁定为正式训练
位置。这个消融比较的是“加入 decoder 适配是否有用”，不是纯粹的等参数层位对照；
后者需要另外调整 rank 使两组参数量匹配，不在当前项目范围。

正式 Clean-LoRA 和 MCT-LoRA 均使用同一 20 小时清单、三个 epoch、有效 batch 16、
encoder+decoder Q/V 与 `r=8`。MCT 只把每个 epoch 的输入确定性地分为 50% clean /
50% raw reverb，样本数和 optimizer steps 不变。最终 dev 选择结果为：

| 训练方式 | 最佳 epoch | Clean CER | Reverb CER | Heavy CER |
|---|---:|---:|---:|---:|
| Clean-LoRA | 3 | 7.31% | 13.29% | 16.13% |
| MCT-LoRA | 3 | **7.15%** | **12.58%** | **15.12%** |

MCT 正式训练在 RTX 4070 上约 4 小时 20 分钟，PyTorch 记录的峰值 GPU allocated
memory 约 1.19 GiB。Clean 训练曾在第三个 epoch 评测前中断并恢复，其
`training_summary.json` 只统计恢复进程的 elapsed time，因此不把该数字当作完整
训练耗时。两组 adapter 都在进入 test 前按 dev Reverb CER 锁定为 epoch 3。

证据文件位于服务器
`runs/<experiment_id>/{run_config.json,eval_metrics.jsonl,training_summary.json}`；训练数据、
adapter 和运行日志按仓库边界不进入 Git。
